对重复输入的前缀（比如系统提示词）进行缓存服用，跳过重复计算，仅处理增量内容
降低成本 费用降低50%-90%
提速，首token降低延迟50%-80%
成系统提示词，rag上下文，多轮对话

# 原理
首次请求需要计算完整输入，缓存中间的key-value状态

后续请求检测相同的前缀，服用key-value缓存，仅计算新内容

# 注意事项
一定要精确匹配 空格 换行 差异都会导致缓存失败
 缓存时间一般是5-10分钟

# 多头机制 transformer的计算特点
后边基于前边的计算

斐波那契数列
第三项开始，每项=前两项之和

prompt缓存机制，使用了前缀缓存和kv缓存
前缀缓存 缓存的事输入文本的前缀字符串，匹配相同开头的请求，复用计算结果
kv缓存 key value cache  transformer中间状态，跳过重复部分的模型计算

例如 
第一次：你是谁？
会计算“你”的结果 v1
计算“你是”的结果 v2
计算“你是谁”的结果v3
计算“你是谁？”的结果v4

第二次：你是谁？今天天气怎么样
复用v4 仅计算后边的
